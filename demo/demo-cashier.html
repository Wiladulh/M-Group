Ringkasan member

Pembayaran saldo memerlukan validasi kartu, PIN, status member, saldo terbaru dan idempotensi oleh server. Cache saldo perangkat tidak boleh menggantikan otorisasi server.

Kebijakan setelah transaksi

Perangkat akan mencoba mengambil saldo terbaru dari server. Jika server tidak dapat memverifikasi saldo, pembayaran saldo ditolak—tidak menggunakan saldo cache sebagai izin transaksi.

Prosedur operasional

Pada sistem nyata, server memvalidasi otorisasi operator dan referensi unik, menulis kredit ledger secara atomik, lalu mengembalikan saldo terbaru. Pengulangan permintaan tidak boleh menggandakan top-up.

Saldo yang benar

Saldo yang ditampilkan di sini hanya data contoh lokal. Di perangkat terpasang, saldo yang sah berasal dari server/ledger. Pembaruan cache setelah transaksi hanya membantu tampilan dan tidak memberikan izin transaksi offline.

Pengamanan kartu

Pendaftaran harus dilakukan oleh operator yang berwenang. UID kartu tidak cukup sebagai autentikasi; server mengikat kartu ke member dan tidak menyimpan UID mentah pada metadata transaksi. PIN transaksi wajib untuk pembayaran.

Informasi perangkat

Konfigurasi hanya ditampilkan, belum disimpan ke perangkat.

Provisioning & keamanan

Device ID dan Device Key diterbitkan server. MAC/hardware ID bukan kredensial rahasia. Setelah instalasi, ganti PIN awal, gunakan HTTPS untuk API, dan jangan tampilkan kembali Device Key setelah provisioning.
