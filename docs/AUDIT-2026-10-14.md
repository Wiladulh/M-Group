## Fixes prepared on this branch

### 1. Daily audit report end boundary

**Finding:** The day filter used created_at < 'YYYY-MM-DD 23:59:59', excluding transactions timestamped exactly at 23:59:59.

**Change:** Use the next calendar day as the exclusive end boundary ([start, next_day)).

**Regression test:** tests/test_audit_date_boundaries.py inserts a cashier deposit at 23:59:59 and asserts it appears in that day's report.

### 2. Vending Excel export ordering/date filter

**Finding:** The vending export joins vending_transactions and vending_machines, both of which contain created_at. An unqualified ORDER BY created_at can be ambiguous. The prior date-filter insertion also generated an unqualified created_at predicate against the joined tables.

**Change:** Qualify the vending sheet's ordering and apply date filtering in an outer query over the selected export columns.

**Regression test:** tests/test_backup_export_date_filter.py verifies both unfiltered joined export and a date-filtered export.

### 3. Audit Excel export authorization and filename normalization

**Finding:** The export route called the report handler without forwarding the already-validated admin token, so the handler rejected the request. The raw query date was also used in the output filename instead of a normalized validated date.

**Change:** Forward the token to the report handler, then build the filename from the validated report's normalized source, period, and start date.

**Regression test:** tests/test_audit_export_endpoint.py verifies unauthenticated requests are rejected and an authenticated request returns a valid XLSX response at the normalized path.

### 4. NFC card ownership validation before revocation

**Finding:** The route revoked a card before checking whether the card belonged to the member ID in the URL. A mismatched URL could therefore revoke another member's card and only then return 404.

**Change:** Confirm the card is listed under the requested member before performing the revocation.

**Regression test:** tests/test_nfc_revoke_ownership.py checks a mismatched member/card URL returns 404 and leaves the card active.

### 5. Interactive custom installation prefix

**Finding:** The installer derived `VENV` and `BIN_DIR` before prompting for a custom application prefix. If an operator changed the prefix interactively, the script could still create/use the virtual environment and scripts under the original prefix.

**Change:** Recompute the derived paths after interactive overrides and add a regression test that guards the ordering.

**Regression test:** `tests/test_linux_installer.py::test_interactive_custom_prefix_updates_derived_install_paths`.

## Remaining review risks — not yet changed

1. **Restore safety and operational recovery:** the restore endpoint now creates a retained native backup of the current live database before replacing it and returns the snapshot filename. Regression coverage is in tests/test_restore_pre_snapshot.py. Production rollback still requires an operator to verify the snapshot exists and is usable before restore.
2. **Legacy database migration coverage:** CI tests fresh/repeatable migrations and integrity checks, but a representative copy of each supported older production schema should be upgraded in a disposable environment before deployment.
3. **Transaction concurrency:** Continue reviewing payment/deposit/vending state transitions under concurrent requests and process interruption. Unit tests alone do not prove device/server reconciliation under power loss.
4. **Security deployment:** Require a strong admin token, keep the raw app port off the public internet, and protect the Cloudflare hostname with Cloudflare Access/TLS. Verify service environment/config file permissions on the target OpenRC host.
5. **Hardware-only acceptance:** Test NFC readers, Wi-Fi reconnect, keypad/LCD, sensors, servo actuation, dispense failure, refund/reconciliation, and retry after power loss on the actual boards.
