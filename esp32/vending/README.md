# M-Group ESP32-S3 Vending — RC522 / PN532 Auto Detect

Vending supports both RC522 and PN532. Startup probes PN532 first, then falls back to RC522 automatically.

## Libraries

Install from Arduino Library Manager:
- Adafruit PN532
- MFRC522
- Adafruit GFX Library
- Adafruit SSD1306
- ESP32Servo

## Default reader wiring

PN532 I2C:
- SDA GPIO 8
- SCL GPIO 9
- IRQ GPIO 7
- RESET GPIO 10

RC522 SPI:
- SCK GPIO 12
- MISO GPIO 13
- MOSI GPIO 11
- SS GPIO 14
- RST GPIO 15

Change constants in `esp32/vending/MGroupVending.ino` for the actual ESP32-S3 board and wiring.

The UID is converted to nfc-<lowercase hexadecimal UID>. The M-Group server remains authoritative for credential, account, balance, stock, transaction, and refund state.


## Mini WebUI configuration

- On first boot without saved settings, vending opens a temporary Wi-Fi network named MGroup-Setup-XXXXXX; setup password and http://192.168.4.1/ are printed to Serial Monitor at 115200 baud.
- To reopen setup later, reboot while holding SELECT (GPIO 6) low. The setup AP password is regenerated on each setup-mode boot.
- Enter Wi-Fi SSID/password, server URL, the Machine ID created in the M-Group dashboard, and the one-time Device Key generated by Dashboard > Perangkat > Generate Key. The key and Machine ID are stored in ESP32 NVS and never displayed back by the portal. Firmware registration and heartbeat send the Device Key and device type only; MAC address is not used for server identity.
- After save, the device restarts and registers using the one-time Device Key only. If registration fails, it retries and blocks vending until registration succeeds.

## Server configuration

Set Wi-Fi/server defaults and `M_GROUP_DEVICE_KEY` in `esp32/vending/MGroupVending.ino` only for development fallback; production configuration should be entered through the mini WebUI.

- `M_GROUP_BASE_URL` must be the M-Group server's reachable LAN address, for example `http://192.168.1.10:8011`; replace the example IP and do not add a trailing slash.
- M-Group defaults to `M_GROUP_HOST=127.0.0.1`, which is loopback-only. For LAN device access, start the server with `M_GROUP_HOST=0.0.0.0 M_GROUP_PORT=8011` (or bind to the server's LAN interface) and allow TCP 8011 only from the trusted LAN in the firewall.
- Generate a Device Key for type `esp32-s3-vending` in the server dashboard and enter it in the mini WebUI together with the matching Machine ID. On first authenticated use, the server binds that key to the machine; subsequent requests must use the same key.
- Each machine exposes fixed public Product IDs `1`–`5`; Product ID determines the physical slot and servo channel. The server keeps internal database product keys private so the same public Product ID can exist on different machines.
- The product API returns `enabled` as a JSON boolean. The firmware uses Product ID, name, price, stock, enabled state, and server-derived servo channel from that response.

Firmware CI validates compilation only; NFC reads, Wi-Fi reachability, servo behavior, dispensing feedback, and real transaction reconciliation still require physical-device tests.
